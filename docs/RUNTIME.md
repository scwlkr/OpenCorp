# Local employee runtime

`LocalRuntime` in `src/runtime/index.ts` supervises OpenCode 1.18.30 through the matching SDK v2. OpenCode owns the conversation, tool loop, and compaction. OpenCorp supplies a durable run, employee, role, assignment, workspace, exact local profile, and scoped MCP broker. A new OpenCode session is durably bound through `onSession` before any inference or corporate tool call. The OpenCode server exits after the run; employees do not require resident runtime processes.

## Models and resources

An owned Ollama 0.32.13 process uses a private HOME, private manifest directory, loopback port, `OLLAMA_NO_CLOUD=1`, one concurrent request, and one resident model. It reuses the existing `~/.ollama/models/blobs` by symlink. Only the three permitted source manifests enter the owned directory. Original aliases and applications' profiles are unchanged. The small Qwen3.5:4b artifact is downloaded through the free Ollama registry when `installModels()` is explicitly run.

Stable model keys are `qwen-main`, `nemotron`, and `small`. Each has private 16K and on-demand 32K profiles, with bounded output of 4096 tokens and temperature 0.2. Explicit profiles are necessary because a source model's `num_ctx` can override the service default. Identity includes the complete private manifest digest, template digest, normalized parameters, context, and local-only policy. Every layer must exist at its declared size; every request rechecks the manifest. Small Qwen advertises vision; the installed large artifacts are text/tool models. The large Qwen uses the owned `qwen-no-thinking-v1` profile: the gateway enforces `reasoning_effort: "none"` on every inference, including compaction, and removes the competing nested `reasoning` option. This profile is part of artifact identity and retained run evidence. Nemotron and the small model retain their existing inference options.

One run owns the inference slot. Main, title, and compaction requests select that run's same local model. The gateway serializes requests and limits them to 36 per run, including at most 32 tool-enabled employee model steps. Exhausted run/step limits return non-retryable errors. No hosted model or fallback is configured. Idle residency is 60 seconds. A run defaults to a 45-minute hard deadline, including canonical checks. The four-minute idle watchdog applies only while no tool or admitted inference is active. Local decoding can buffer tool arguments without emitting response bytes; an admitted request remains subject to the original hard deadline and immediate cancellation. Actual running tools also retain their bounded tool timeout. No sleep/power settings are modified.

## Native boundary

The entire headless OpenCode process tree is wrapped by the pinned macOS sandbox implementation from `@anthropic-ai/sandbox-runtime` 0.0.75. Workers can read their workspace, their own runtime HOME, pinned dependencies/toolchain, and their worktree's shared Git metadata. Only the workspace and own HOME are writable. Broad read denials cover Owner files, company state, other workspaces, temporary directories outside that HOME, credentials, repository secret files, and imported runtime configuration. Shared Git metadata remains read-only; the trusted broker performs commits and remote operations.

Workers receive a newly constructed environment. No inherited token, credential socket, shell startup hook, or Owner HOME is passed. Global Git configuration is disabled. Native restrictions remain in force when a workspace script invokes additional processes. The selected Apple Xcode installation is discovered through `xcode-select`, admitted read-only, and its compiler/SDK paths are configured directly; compiler caches remain in owned paths.

Two upstream defaults are deliberately narrowed in the wrapper, without modifying the installed dependency:

- `allowLocalBinding` remains false: upstream enabling it would permit every localhost destination. Only the exact run gateway and runtime server bind/inbound ports are included. Outbound access to the runtime's own control-server port is then removed, preventing workspace scripts from creating untracked sessions.
- The generic profile's Keychain Mach service is removed. Apple Events and Unix sockets remain disabled. Credentialed integrations belong to the outside broker.

The model gateway accepts only the assigned model's completion route and the exact corporate MCP route. It rejects HTTP proxy requests, CONNECT tunnels, WebSocket upgrades, unrelated loopback routes, cloud model names, and unassigned models. The real broker token stays outside the sandbox. MCP forwarding supplies the actual bound runtime session header. The broker must additionally validate current policy, employee/run binding, lifecycle and cost at action time. Cancellation closes the gateways before terminating the owned coalition, so late calls cannot dispatch new effects.

`executeSandboxed` exposes the same OS boundary to canonical repository checks. Its default network channel rejects everything. Trusted callers may supply preselected ports and toolchain read paths; those options must never be accepted from model-supplied tool arguments. Exit 124 means timeout; 130 means cancellation.

Each owned tree runs in a unique temporary launchd job with its own kernel resource coalition. An outside guardian records PID, kernel process unique ID, coalition, and boot identity durably before spawning the employee. The small native helper in `src/runtime/process-identity.c` enumerates coalition members, freezes them before termination, validates identities before signaling, and confirms no live members remain. This also covers detached and reparented grandchildren which escape ordinary process-group termination. A guardian notices daemon death and cleans its coalition. Jobs are removed when finished; explicit stop verifies native absence rather than treating an elapsed timeout as proof.

`recoverRun(runId)` reads the durable receipt and reports `absent`, `running`, or `uncertain`. Proven orphan coalitions are cleaned before recovery. Missing/malformed receipts stay uncertain; the scheduler must use its own recorded preparation stage to reconcile work claimed before runtime dispatch. An owned Ollama restart also reconciles its previous receipt before creating a replacement. Startup generation cancellation prevents a pending asynchronous initialization from launching a service after stop. The helper is compiled locally from the installed source checkout to a hash-named owned control path; compilation needs the already installed Apple developer tools.

`recoverTools()` additionally enumerates every native job's durable launch intent and receipt before scheduler reclaim, including dependency installation performed before employee dispatch. It reaps only positively identified orphan coalitions; an identity mismatch stays uncertain and is never signaled. Finished jobs with no live members are positively absent even when their historical supervisor no longer exists. Native observation retries account for processes transitioning to zombies; elapsed time alone never establishes absence. A real crash test suspends the guardian, kills its supervisor, and verifies startup recovery kills a detached installer descendant before it can write a delayed sentinel.

## Integration exports

```ts
const runtime = new LocalRuntime({ dataRoot, onEvent });
await runtime.start();
const models = await runtime.models();
const result = await runtime.execute({
  runId, employeeId, workspace, modelId, system, prompt,
  brokerUrl, token, onSession, onEvent, signal,
  // Optional: imagePaths, contextTokens (16384 or 32768), timeoutMs,
  // toolEnvironment from the trusted dependency adapter.
});
await runtime.cancel(runId);
await runtime.stop();
```

Results contain the actual session, text, model/profile identity, reported token usage, request count, duration, and retained message file. Run history lives under `runtime/employees/<run-id>/`. These are runtime records; the company database remains the authority for assignments and completion.

Local completion requests use signal-owned HTTP to the exact owned loopback endpoint, without redirects or Node fetch's implicit 300-second header/body timeouts. Admission begins after identity and budget checks and ends on response completion, failure or cancellation. Only actual response bytes produce progress events.

The local provider also sets `headerTimeout: false`, `chunkTimeout: false`, and `timeout: false` through OpenCode's supported provider options. [OpenCode 1.18.30](https://github.com/anomalyco/opencode/blob/v1.18.30/packages/opencode/src/provider/provider.ts#L1687) otherwise adds its own 300-second response-header and SSE-chunk timers even though it disables Bun's native fetch timeout. Buffered local tool arguments remain governed by OpenCorp's original 45-minute run deadline and cancellation; request, step, output and continuation limits are unchanged.

OpenCode prompts use asynchronous admission followed by bounded status/message reads. This avoids Node's five-minute response-header timeout during a legitimate long tool sequence. A real small-model run lasting 337 seconds, including an unchanged 310-second shell command and subsequent file read, passed. Known Ollama Qwen truncation errors are converted to `400/context_length_exceeded` so OpenCode compacts instead of repeatedly retrying an unchanged oversized request; other upstream statuses are preserved. The original histories remain durable.

A native `ContextOverflowError` event is recoverable while OpenCode is busy or retrying: the pinned prompt loop emits it before starting its own compaction. OpenCorp keeps polling under the original signal, deadline and cumulative budgets. At idle it requires a genuine completed answer or retains the actual terminal assistant error; an unresolved overflow still fails. Other session errors remain immediate. Recovery does not inject a new prompt, reset a budget or manufacture a successful finish. Run input/output token totals sum all requests; they are not the size of one context window.

OpenCode 1.18.30 checks the last completed turn's tokens before adding new tool results. Both profiles declare an explicit input limit so its compaction reserve takes effect: 32K reserves 8192 tokens and compacts at 24,576; 16K preserves its existing 4096 reserve and 12,288 threshold. The extra 32K margin accommodates subsequent tool results. Every scheduled company turn uses 32K: actual initial governance input reached 13,027 tokens before output or tool results, and compaction cannot remove the fixed assignment/tool prompt floor. The standalone runtime retains 16K support for explicitly bounded disposable tasks. Model assignments and the single inference slot are unchanged.

A completed response with `finish: length` is output exhaustion, not successful assignment completion. The runtime snapshots messages and model/usage/finish provenance, then permits at most two explicit continuations in the same OpenCode session. The original run deadline, 36-request allowance and cumulative 32-step allowance remain unchanged. Continuation admission must observe a new assistant message and refuses a conversation changed since its last checkpoint. Repeated exhaustion throws `RuntimeExecutionError` with code `output_limit_exhausted` and the retained `RuntimeResult`; other run/step failures use their corresponding budget codes. Every completed reply writes `result.json` and `messages.json` before continuation. The scheduler must retain that result before validating company outcomes, and preserve `error.result` on failure. Partial/incomplete work never becomes success solely because the provider stopped generating.

Failure capture also runs when a provider/budget event arrives before the first reply checkpoint. It uses an independent 1.5-second diagnostic request, then an owned read-only SQLite snapshot if the server is unavailable; cancellation reads the database directly. The snapshot includes the latest interrupted continuation and explicitly marks an incomplete assistant. `RuntimeExecutionError.evidence` always retains selected model identity, reported usage and the actual failure record; session/message paths are optional when unavailable. The scheduler must also preserve this evidence when no assistant result exists. A missing message is never replaced with a fabricated completion.

## Isolated product dependencies and local tests

`prepareProductDependencies({productName, workspace, dataRoot, signal})` in `src/tools/dependencies.ts` prepares only owned product workspaces. It returns `{installed, environment, checks, receiptPath, artifacts, downloaded, reused, incrementalCost: 0}`. `productToolEnvironment({workspace, dataRoot})` reads its protected receipt. Pass that environment to `runtime.execute` and `executeSandboxed`; never accept environment or filesystem grants from employee tool arguments.

OpenJob uses installed Node 22.22.3; paletteWOW uses Ruby 3.4.8 and Bundler 4.0.7. The adapter reads locked public artifact URLs and verifies npm SHA512 or Ruby SHA256 checksums, reuses only verified public cache content, and fetches missing artifacts without credentials from explicit npm/RubyGems endpoints. Package/lifecycle/native-extension installation runs offline inside the native sandbox. Browser archives use only explicit public Playwright/Chrome-for-Testing URLs, with every redirect validated and source/digest receipts retained; extraction also runs inside the sandbox. Original product dependencies and shared model profiles are preserved. Installation caches are separate per workspace.

`executeSandboxed({localTestNetwork: true, toolEnvironment, ...})` adds a dedicated proxy for local test HTTP services. Product employee runs with a prepared tool environment receive the same facility. The kernel permits loopback binding but still denies direct outbound connections except to the assigned gateways. Before forwarding any bytes, the proxy verifies that every destination listener belongs to the worker's kernel coalition; it repeats this check after connecting to reject listener replacement. Owner services, other workers and the employee's OpenCode control port remain denied. Node's environment proxy support and a protected Playwright preload route compatible test clients through this boundary. Chromium receives narrowly named Mach rendezvous permissions for its subprocesses, with Keychain and Apple Events still denied.

Actual verification covered an ephemeral Node HTTP server and Chromium 149 navigation to an owned service while an unrelated Owner sentinel HTTP endpoint received zero requests. Local HTTP clients that ignore proxy settings fail closed.

For paletteWOW, dependency preparation fetches a concrete public RubySec database revision, the canonical importmap package inventory's npm advisory response, and public Brakeman release metadata without credentials. Only exact fixed endpoints are used; package query fields are bounded and validated. Protected snapshots expire after one hour. A read-only Ruby preload substitutes the cached transport response; stock vulnerability checks and Brakeman's ensure-latest decision remain intact. RuboCop searches the product checkout's configuration sources without traversing Owner or other product directories.

## Verification

`tests/runtime.test.ts` executes native denial attempts from a spawned workspace script, including protected file reads/writes, a symlink, a child process and an arbitrary localhost endpoint. It also checks fresh environment construction, pre-dispatch hosted-inference denial, bounded cancellation, detached grandchildren, before/after-spawn startup races and the actual selected C compiler. These are real sandbox attempts with controlled sentinel files, never reads of Owner secrets.

`npm run verify:local-runtime` performs a disposable Qwen implementation, a separate Nemotron review at 32K, the fixture's executable checks, a small-model inspection of an actual Playwright screenshot, and runtime cancellation. It retains an explicit JSON record outside the source checkout. This fixture proves integration; it does not count as autonomous product delivery. `verify:acceptance` must establish that separately.

Sources: [OpenCode SDK](https://opencode.ai/docs/sdk/), [configuration](https://opencode.ai/docs/config/), [Ollama FAQ](https://docs.ollama.com/faq), [Sandbox Runtime](https://github.com/anthropic-experimental/sandbox-runtime).

Trusted governance votes and failed-run diagnoses may request one actual final response after the scheduler recomputes their existing current-run checkpoint. At the next employee inference boundary, OpenCorp confirms the native session is busy and all prior tool parts have settled, retains an exclusive intent, and calls pinned OpenCode `session.prompt` with `noReply:true` and every observed tool disabled. This stores a real user request in the same running session without starting another loop. The already-constructed request also loses its stale tool definitions at the gateway; Ollama does not implement `tool_choice`. Both that response and the following native response remain real, counted model work. Completion waits for a response to the stored final request or its later native continuation, and the scheduler still validates the actual checkpoint. Conversations, product work, reviews, delivery and ordinary management are excluded.

The receipt `runtime/employees/<run>/final-response.json` and result/failure diagnostics retain admission status and actual native message identity. Uncertain admission is never replayed. The callback is checked again after the actual final reply is retained and at scheduler completion. A changed assignment or authority is an interrupted/superseded run, preserving the real response and current Owner disposition without creating a model-failure diagnosis. Original cancellation, 45-minute deadline, 36 inference requests, 32 tool-enabled steps, 4096 output limit and at most two length continuations remain; those continuations retain the tool-free final-response phase. Already-idle sessions and the native step-limit boundary are not steered. Supported behavior is pinned in [OpenCode prompt/noReply](https://github.com/anomalyco/opencode/blob/v1.18.30/packages/opencode/src/session/prompt.ts) and [per-user tool filtering](https://github.com/anomalyco/opencode/blob/v1.18.30/packages/opencode/src/session/llm/request.ts); no assistant text or successful native finish is manufactured.
